# 使用指南

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 配置环境变量

复制 `.env.example` 并创建 `.env` 文件：

```bash
cp .env.example .env
```

编辑 `.env` 文件，填入你的 API Keys：

```env
# 至少需要配置一个 API Key
ANTHROPIC_API_KEY=sk-ant-xxxxx
OPENAI_API_KEY=sk-xxxxx
GOOGLE_API_KEY=xxxxx

# 可选配置
DEFAULT_MODEL_PROVIDER=anthropic
ENABLE_THREE_AGENT_MODE=true
DEBATE_ROUNDS=3
```

### 3. 运行程序

#### 开发模式

```bash
npm run dev
```

#### 构建并运行

```bash
npm run build
npm start
```

## 使用模式

### 交互式模式（推荐）

完整体验三 Agent 协同工作流程：

```bash
dao-code interactive
# 或
dao-code i
```

这个模式会引导你完成：
1. 输入需求
2. 观看三 Agent 辩论
3. 选择最佳方案
4. 三 Agent 协同编码
5. 获得最终代码

### 需求澄清模式

只运行需求澄清阶段，产出技术方案：

```bash
dao-code clarify
# 或
dao-code c
```

适用场景：
- 项目初期的技术选型
- 需要多角度评估方案
- 想要看 AI 辩论过程

### 菜单模式

显示主菜单，可以多次执行不同操作：

```bash
dao-code menu
# 或
dao-code m
```

### 默认模式

直接运行会显示选项菜单：

```bash
dao-code
```

## 工作流程详解

### 阶段一：需求澄清

三个 Agent 会进行深度辩论：

1. **第一轮**
   - 正方：提出 2-3 个初步方案
   - 反方：质疑每个方案的问题
   - 裁判：记录要点

2. **第二轮**
   - 正方：完善方案，回应质疑
   - 反方：继续深挖潜在风险
   - 裁判：综合分析

3. **第三轮**（最终轮）
   - 正方：最终优化
   - 反方：最后检查
   - 裁判：产出 3 个最佳方案供选择

### 阶段二：编码协同

三个 Agent 采用极限编程模式：

1. **第一轮**
   - Agent A 编写代码
   - Agent B 实时审查
   - Agent C 质量检查

2. **后续轮次**（如果需要）
   - 角色轮换：A → B → C → A
   - 根据上一轮的问题改进代码
   - 直到通过检查或达到最大轮次

## 自定义配置

### 选择不同的 AI 模型

启动时可以自定义三个 Agent 使用的模型：

```bash
dao-code interactive
# 程序会询问：是否自定义三个 Agent 的模型？
# 选择 Yes，然后为每个角色选择模型
```

推荐组合：

**创新优先**
- 正方：Claude（理解深刻）
- 反方：GPT-4（逻辑严密）
- 裁判：Gemini（多角度分析）

**稳定优先**
- 正方：GPT-4（工程实践）
- 反方：Claude（代码质量）
- 裁判：GPT-4（决策能力）

**成本优先**
- 全部使用 Gemini（性价比高）

### 调整辩论轮次

在 `.env` 中设置：

```env
DEBATE_ROUNDS=5  # 更深入的辩论
```

## 使用示例

### 示例 1：实现用户认证系统

```
需求：实现一个 JWT 认证中间件，支持 token 刷新

辩论结果（三个方案）：
1. 基于 Express 中间件 + Redis 缓存
2. 无状态 JWT + 短期 token
3. JWT + Refresh Token 双 token 机制

选择：方案 3

编码结果：
- 生成完整的认证中间件代码
- 包含错误处理和安全措施
- 通过三轮代码审查
```

### 示例 2：数据库设计

```
需求：为电商系统设计订单表结构

辩论结果：
1. 单表设计（简单但扩展性差）
2. 订单主表 + 订单详情表（经典方案）
3. 事件溯源模式（高级但复杂）

选择：方案 2

编码结果：
- 完整的表结构 SQL
- 包含索引和约束
- 考虑了性能优化
```

## 最佳实践

### 1. 清晰描述需求

❌ 不好的需求：
```
写一个登录功能
```

✅ 好的需求：
```
实现一个基于 JWT 的用户登录系统，需要：
- 支持邮箱和密码登录
- 密码使用 bcrypt 加密
- JWT token 有效期 7 天
- 需要考虑安全性（防止暴力破解等）
```

### 2. 关注辩论过程

不要跳过辩论直接看结果，辩论过程中的质疑和讨论往往能发现重要问题。

### 3. 理性选择方案

不要总是选择"最先进"的方案，根据项目实际情况选择：
- 团队技能水平
- 时间预算
- 维护成本

### 4. 代码后续调整

生成的代码是起点，不是终点。根据实际项目需求进行调整：
- 添加项目特定的错误处理
- 集成到现有代码库
- 添加测试

## 故障排除

### API Key 问题

**错误**：`API key is required for anthropic`

**解决**：
1. 检查 `.env` 文件是否存在
2. 确认 API Key 格式正确
3. 重新启动程序

### 网络问题

**错误**：`API request failed`

**解决**：
1. 检查网络连接
2. 确认 API 服务是否可用
3. 考虑使用代理

### 模型配额

**错误**：`Rate limit exceeded`

**解决**：
1. 等待一段时间后重试
2. 切换到其他模型
3. 升级 API 账号
